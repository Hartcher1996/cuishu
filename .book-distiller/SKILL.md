# Book Distiller

将任意一本书蒸馏成一页单文件 HTML，**让低学历人群也能快速学到书籍精华**。

蒸馏 = 翻译：把"专业人士写给专业人士看的书"，翻译成"普通人能懂的精华"。

## 何时调用

当用户提出以下类型的请求时：
- "帮我把《XXX》蒸馏成一页 HTML"
- "我想学习《XXX》，帮我做个精华版网页"
- "把这本书做成单页 HTML 学习笔记"
- 任何涉及将书籍内容浓缩、蒸馏、提炼为单页 HTML 文件的请求

---

## 一、通俗易懂（最重要，每条内容都要过）

这是蒸馏的**使命**，不是口号。下面 5 条是硬性检查项，每写一段内容都要对照一遍。

### 1. 术语必须翻译

任何专业术语首次出现时，**紧接着用日常生活中的事物或情境解释一遍**。解释要能让没读过这本书的人也听懂。

### 2. 抽象概念必须类比

遇到看不见摸不着的概念（公式、原理、心理机制、商业模式…），**用生活中常见的事物打个比方**。读者应该能通过这个比方直接理解概念的本质。

### 3. 避免学术腔

低学历读者能看懂长句子。他们读不下去的是**学术腔**：堆砌术语、长定语、被动句、嵌套从句、绕弯子。

- ❌ "当一个变量发生变化时，与之相关的另一个变量也随之发生同方向的变化，这种现象被称为正相关。"
- ✅ "A 变多，B 也变多。这种关系叫正相关。"

- ❌ "该理论的核心要义在于通过对个体心理机制的系统性分析以揭示群体行为的内在规律性。"
- ✅ "这本书要讲一件事：为什么人一到群体里，就变了一个人。"

**判断标准不是字数，而是是否绕弯子**。一句话能讲清的事，不要拆成三句；一个意思需要 30 字才能讲清的，不要硬压到 15 字。

**例外**：`.quote` 里的金句作为原书摘录，保留原文不改写。

### 4. 禁止假设前置知识

不要说"如前所述""众所周知""经典的 X 理论""相信大家都知道"。**永远假设读者什么都不知道，从头讲起。**

### 5. 金句必须能行动

摘录金句时，**只摘"读完能立刻做一件事"的话**，不摘"看起来有道理但不知道怎么用"的格言。每条金句后面用一句话说清楚"读完能做什么"。

## 二、3 条红线（不能碰）

### 1. HTML 骨架

读取同目录 `template.html` 作为骨架，**不要修改其中的 `<style>` 和 `<script>` 块**。布局、CSS、JS 交互全部复用。

### 2. 阅读器兼容 class

以下 class 会被书籍蒸馏阅读器的 TTS 引擎识别为可朗读段落，**必须出现**：

| class | 用途 |
|---|---|
| `section` | 章节容器（带 `id` 属性作锚点） |
| `h2` / `h3` / `h4` | 章节标题 |
| `.callout-title` | 提示框标题 |
| `.info-box-title` | 信息框标题 |

### 3. 图标

使用内联 Lucide 线性 SVG，**禁止使用 emoji**。

```html
<svg class="icon" xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24"><path d="..."/></svg>
```

## 三、骨架用法

### 1. 读取 template.html

作为蒸馏产物的 HTML 骨架。所有布局、样式、交互已就位。

### 2. 填充内容

- 每个章节用 `<section id="xxx">` 包裹（id 是锚点）
- **`<section>` 内的 `<h3>` / `<h4>` 也要设 `id` 属性**，作为子章节锚点（如 `<h3 id="sub-xxx">`）
- 章节内容填入 `<main class="main">` 内的 `.content` 区
- Hero 区 `<section class="hero">` 填书名、作者、一句话定位
- 页脚 `<footer class="book-footer">` 填书名

### 3. 生成目录

`<aside class="toc">` 内的 `<ul>` 由章节自动生成：

- 一级章节用 `<li class="toc-h2"><a href="#xxx">章节名</a></li>`
- **二级子章节嵌套在一级章节下**：`<li class="toc-h2"><a href="#xxx">章节名</a><ul><li><a href="#sub-xxx">子章节</a></li></ul></li>`
- **`<h3>` / `<h4>` 的 id 必须加入 TOC 二级嵌套**——不能只把一级章节放进 TOC
- 确保 `<a href="#xxx">` 与 `<section id="xxx">` 一一对应
- 确保 TOC 二级嵌套的 `<a href="#sub-xxx">` 与 `<h3 id="sub-xxx">` / `<h4 id="sub-xxx">` 一一对应
- **逐一核对**：正文里每个 `<section id>`、每个 `<h3 id>`、每个 `<h4 id>` 都要在 TOC 里找到对应链接。一个都不能漏。

### 4. 可用组件清单（template.html 已内置样式）

| 组件 | class | 典型用途（仅供参考，不强制） |
|---|---|---|
| 提示框 | `.callout` + `.callout-title` | 术语解释、坑点提醒 |
| 提示框变体 | `.callout.tip` / `.callout.warn` / `.callout.case` | 不同语义的提示 |
| 概念卡 | `.card.concept` + `.card-num` | 核心观点编号 |
| 金句卡 | `.quote` + `.quote-source` | 金句摘录 |
| 信息框 | `.info-box` + `.info-box-title` | 关键数据、定义 |
| 编号步骤 | `.steps` | 操作流程 |
| 知识图谱 | `.km` + `.km-level` + `.km-items` | 体系关系图 |
| 章节结构 | `.chapter` + `.chapter-num` + `.chapter-header` | 分章精读 |

**哪个好用哪个，不强制用哪些、不强制用几个。**

## 四、AI 的自由度

### 结构自由

这本书适合怎么组织就怎么组织。**不规定"必须有 N 个模块"，不规定模块名称。**

理论书、技术书、小说、传记、哲学、商业、园艺、烹饪——不需要先归类，直接按内容自己决定结构。

### 组件自由

`.callout` 可以装术语解释、可以装坑点提醒、可以装延伸阅读——**由内容决定，不是由 class 名决定**。

### 取舍自由

不重要的章节可以跳过、可以一句话带过。重要的概念可以多讲、可以反复讲。**别为了"覆盖全书"而稀释精华。**

### 风格自由

可以像聊天一样（"想象一下..."），可以像讲故事一样（"有个人..."），可以像列清单一样。**只要能让人懂，什么风格都行。**

## 五、执行步骤

### 第一步：调研书籍内容
1. 使用 WebSearch 搜索书籍的目录、核心内容、读书笔记
2. 查找权威的书评、课程笔记、官方介绍
3. 多源交叉验证，确保内容准确
4. 梳理书的章节结构和核心论点

### 第二步：规划内容结构
1. 根据书的内容自主决定章节结构（不要套固定模板）
2. 为每个章节提炼核心要点
3. 设计目录层级
4. 为每个章节匹配 Lucide 图标

### 第三步：生成 HTML 文件
1. 读取同目录 `template.html` 作为骨架
2. 将蒸馏内容填入 `<main class="main">` 内的 `<section>` 块
3. 为每个 `<section>` 设置唯一 `id`
4. 同步生成 `<aside class="toc">` 内的目录列表
5. 确保所有可朗读段落使用规定的 class
6. 输出文件保存到工作区根目录，命名格式：`《书名》精华版.html`

### 第四步：质量检查

**通俗易懂检查（5 条，每段内容都要过）：**
- [ ] 专业术语首次出现时，是否用日常事物解释了一遍？
- [ ] 抽象概念是否用了生活中的比方？
- [ ] 是否避免了学术腔（堆术语、长定语、被动句、嵌套从句、绕弯子）？
- [ ] 是否有"如前所述""众所周知"等假设前置知识的表达？
- [ ] 金句是否都是"读完能做一件事"的话？是否补了"能做什么"？

**骨架红线检查：**
- [ ] 是否基于 template.html 生成？
- [ ] `section / h2 / h3 / h4 / .callout-title / .info-box-title` 是否都出现？
- [ ] 目录 `<a href="#xxx">` 与 `<section id="xxx">` 是否一一对应？
- [ ] **`<h3>` / `<h4>` 是否都设了 `id` 并加入 TOC 二级嵌套？**（不能只把一级章节放进 TOC）
- [ ] 图标是否都是内联 SVG（无 emoji）？
- [ ] 移动端布局是否正常（≤960px 时目录应可折叠）？
- [ ] 滚动高亮是否正常（滚动某章节时目录对应项高亮）？

## 七、注意事项

1. **内容准确性**：通过多个来源交叉验证核心概念，避免错误
2. **版权意识**：这是学习笔记性质的蒸馏，引用原书内容要注明出处，不要大段原文照搬
3. **单文件原则**：输出 HTML 必须是单文件（所有 CSS/JS 内联），不能有外部依赖
4. **性能优先**：页面应该秒开，不要加不必要的动画和特效
5. **可打印性**：template.html 已内置打印样式，不要破坏
