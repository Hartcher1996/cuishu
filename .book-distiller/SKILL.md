# Book Distiller

将任意一本书蒸馏成一页单文件 HTML，**让低学历人群也能快速学到书籍精华**。

蒸馏 = 翻译：把"专业人士写给专业人士看的书"，翻译成"普通人能懂的精华"。

## 何时调用

当用户提出以下类型的请求时：

- "帮我把《XXX》蒸馏成一页 HTML"
- "我想学习《XXX》，帮我做个精华版网页"
- "把这本书做成单页 HTML 学习笔记"
- 任何涉及将书籍内容浓缩、蒸馏、提炼为单页 HTML 文件的请求

## 一、通俗易懂（最重要，每条内容都要过）

这是蒸馏的**使命**，不是口号。下面 5 条是硬性检查项，每写一段内容都要对照一遍。

### 1. 术语必须翻译

任何专业术语首次出现时，**紧接着用日常生活中的事物或情境解释一遍**。解释要能让没读过这本书的人也听懂。

### 2. 抽象概念必须类比

遇到看不见摸不着的概念（公式、原理、心理机制、商业模式…），**用生活中常见的事物打个比方**。读者应该能通过这个比方直接理解概念的本质。

### 3. 避免学术腔

低学历读者能看懂长句子。他们读不下去的是**学术腔**：堆砌术语、长定语、被动句、嵌套从句、绕弯子。

- ❌ "当一个变量发生变化时，与之相关的另一个变量也随之发生同方向的变化，这种现象被称为正相关。"
- ✅ "A 变多，B 也变多。这种关系叫正相关。"
- ❌ "该理论的核心要义在于通过对个体心理机制的系统性分析以揭示群体行为的内在规律性。"
- ✅ "这本书要讲一件事：为什么人一到群体里，就变了一个人。"

**判断标准不是字数，而是是否绕弯子**。一句话能讲清的事，不要拆成三句；一个意思需要 30 字才能讲清的，不要硬压到 15 字。

**例外**：`.quote` 里的金句作为原书摘录，保留原文不改写。

### 4. 禁止假设前置知识

不要说"如前所述""众所周知""经典的 X 理论""相信大家都知道"。**永远假设读者什么都不知道，从头讲起。**

### 5. 金句不硬凑

金句是结果，不是任务。**有几句摘几句，不要为了凑数硬拉。**

- 实用类书：金句后面可以跟"能做什么"
- 思想类/古籍：金句后面跟"这句话在说什么"或"为什么重要"
- 文学/小说类：不叫"金句"，叫"难忘的话"或"值得记住的瞬间"，后面不需要跟"能做什么"

**不要每本书都硬凑 5 句。** 3 句也行，8 句也行，没有也没关系。

## 二、3 条红线（不能碰）

### 1. HTML 骨架

读取同目录 `template.html` 作为骨架，**不要修改其中的 `<style>` 和 `<script>` 块**。布局、CSS、JS 交互全部复用。

### 2. 阅读器兼容 class

以下 class 会被书籍蒸馏阅读器的 TTS 引擎识别为可朗读段落，**必须出现**：

| class              | 用途                 |
| ------------------ | ------------------ |
| `section`          | 章节容器（带 `id` 属性作锚点） |
| `h2` / `h3` / `h4` | 章节标题               |
| `.callout-title`   | 提示框标题              |
| `.info-box-title`  | 信息框标题              |

### 3. 图标

使用内联 Lucide 线性 SVG，**禁止使用 emoji**。

## 三、骨架用法

### 1. 读取 template.html

作为蒸馏产物的 HTML 骨架。所有布局、样式、交互已就位。

### 2. 填充内容

- 每个章节用 `<section id="xxx">` 包裹（id 是锚点）
- **`<section>` 内的 `<h3>` / `<h4>` 也要设 `id` 属性**，作为子章节锚点（如 `<h3 id="sub-xxx">`）
- 章节内容填入 `<main class="main">` 内的 `.content` 区
- Hero 区 `<section class="hero">` 填书名、作者、一句话定位
- 页脚 `<footer class="book-footer">` 填书名

### 3. 生成目录

`<aside class="toc">` 内的 `<ul>` 由章节自动生成：

- 一级章节用 `<li class="toc-h2"><a href="#xxx">章节名</a></li>`
- **二级子章节嵌套在一级章节下**：`<li class="toc-h2"><a href="#xxx">章节名</a><ul><li><a href="#sub-xxx">子章节</a></li></ul></li>`
- **`<h3>` / `<h4>` 的 id 必须加入 TOC 二级嵌套**——不能只把一级章节放进 TOC
- 确保 `<a href="#xxx">` 与 `<section id="xxx">` 一一对应
- 确保 TOC 二级嵌套的 `<a href="#sub-xxx">` 与 `<h3 id="sub-xxx">` / `<h4 id="sub-xxx">` 一一对应
- **逐一核对**：正文里每个 `<section id>`、每个 `<h3 id>`、每个 `<h4 id>` 都要在 TOC 里找到对应链接。一个都不能漏。

### 4. 可用组件清单（template.html 已内置样式）

| 组件    | class                                              | 典型用途（仅供参考，不强制） |
| ----- | -------------------------------------------------- | -------------- |
| 提示框   | `.callout` + `.callout-title`                      | 术语解释、坑点提醒      |
| 提示框变体 | `.callout.tip` / `.callout.warn` / `.callout.case` | 不同语义的提示        |
| 概念卡   | `.card.concept` + `.card-num`                      | 核心观点编号         |
| 金句卡   | `.quote` + `.quote-source`                         | 金句摘录           |
| 信息框   | `.info-box` + `.info-box-title`                    | 关键数据、定义        |
| 编号步骤  | `.steps`                                           | 操作流程           |
| 知识图谱  | `.km` + `.km-level` + `.km-items`                  | 体系关系图          |
| 章节结构  | `.chapter` + `.chapter-num` + `.chapter-header`    | 分章精读           |

**哪个好用哪个，不强制用哪些、不强制用几个。**

## 四、按书的类型组织内容（去模板化核心）

### 先判断：这是一本什么类型的书？

不同类型的书，读者的期待完全不同。**不要用同一套结构去套所有书。**

下面是四类常见书的参考结构——这是建议，不是规定。根据书的具体内容灵活调整。

### 类型 A：实用方法类

（如《影响力》《原则》《穷查理宝典》《快速阅读》等）

**读者期待：** 读完就能用，能立刻改变行为。

**推荐结构：**
1. 开篇：这书在讲什么 + 核心比喻
2. 地基：底层逻辑/核心原理（2-3 条）
3. 主干：全书核心内容（按原书逻辑或重新组织）
4. 组合/进阶：多条原理组合使用的高级用法
5. 行动指南：怎么用（可以分"对自己用""对别人用""避坑"）
6. 金句/速查表（可选）
7. 读法建议 + 局限（短一点，别喧宾夺主）

**收尾可以有"读完做一件事"——因为实用类书就是要行动的。**

### 类型 B：思想经典 / 古籍

（如《孙子兵法》《道德经》《论语》《沉思录》等）

**读者期待：** 改变看问题的方式，获得一种新的思维框架。

**推荐结构：**
1. 开篇：先破一个常见误读（这是抓人的最好方式）+ 一句话核心
2. 作者与成书：人是谁、书怎么传下来的、为什么直到今天还重要
3. 核心思想：拆成 3-5 块讲（不要按原书章节顺序，按逻辑组织）
4. 思维方式：这本书想问题的独特方式（对偶、辩证、系统……）
5. 原文选读：挑 5-10 句最核心的原文，古文在上，白话在下，一句点睛
6. 被误读最多的几句话（专属板块！古籍几乎都有这个问题）
7. 现代怎么用（可选，别太牵强）
8. 版本推荐 + 读法建议

**收尾不要"读完做一件事"。** 思想类书的价值是改变认知，不是立刻行动。可以用"一个值得反复想的问题"来收尾。

### 类型 C：文学 / 小说

（如《堂吉诃德》《百年孤独》《红楼梦》《活着》等）

**读者期待：** 快速了解故事、人物、为什么这本书是经典。

**推荐结构：**
1. 开篇：一句话说完 + 先把结局告诉你（小说不怕剧透）
2. 作者与时代：这个人是谁、为什么写这本书
3. 故事线：按时间线讲主线（砍掉支线和插叙）
4. 核心人物：主要角色分析，2-3 个就够
5. 必读名场面 / 难忘瞬间：3-5 个，讲清楚发生了什么 + 为什么有名
6. 这本书真正在说的：主题解读，3-4 个角度
7. 写法上的独特之处（如果有的话）
8. 它留下了什么：对后世的影响、进入日常语言的说法、被引用的场景
9. 译本/版本怎么选（可选）

**绝对不要：** "X条能带走的东西" + "读完做一件事"。小说不是工具手册，读完不需要立刻行动。

**好的收尾：** 一个留给读者的问题，或者"为什么今天还要读这本书"。

### 类型 D：知识 / 科普类

（如《经济学原理》《时间简史》《自私的基因》等）

**读者期待：** 建立一个领域的知识框架，搞懂一个学科的基本问题。

**推荐结构：**
1. 开篇：这门学科在回答什么问题
2. 核心框架：最基础的几个概念（搭骨架）
3. 主干内容：按逻辑展开（不一定按原书顺序）
4. 最反直觉的几个结论（专属板块！科普书的亮点就在这儿）
5. 常见误解澄清
6. 这个领域目前还回答不了的问题（可选，但加了很显深度）
7. 推荐进阶读法

**收尾：** "读完这本，下一本读什么"，或者"一个值得好奇的问题"。

## 五、AI 的自由度

### 结构自由

这本书适合怎么组织就怎么组织。**不规定"必须有 N 个模块"，不规定模块名称。**

理论书、技术书、小说、传记、哲学、商业、园艺、烹饪——不需要先归类，直接按内容自己决定结构。

### 组件自由

`.callout` 可以装术语解释、可以装坑点提醒、可以装延伸阅读——**由内容决定，不是由 class 名决定**。

同一个组件，不要在一本书里反复用同一种用法。比如 concept 卡片，前面用了列"五事"，后面"X条带走的东西"就换一种呈现方式（可以用 info-box，可以用段落，可以用表格感的排版）。

### 取舍自由

不重要的章节可以跳过、可以一句话带过。重要的概念可以多讲、可以反复讲。**别为了"覆盖全书"而稀释精华。**

### 风格自由

可以像聊天一样（"想象一下..."），可以像讲故事一样（"有个人..."），可以像列清单一样。**只要能让人懂，什么风格都行。**

但要注意：**风格要跟书的气质匹配。** 讲《孙子兵法》可以沉稳一点，讲《堂吉诃德》可以活泼一点，讲《影响力》可以亲切一点。

## 六、去模板化检查（蒸馏完必过）

蒸馏完一本书，对照下面 5 条问自己，如果有 3 条以上答"是"，说明模板化了，回去改：

- [ ] **结尾三件套：** 是不是又用了"金句 + 读法 + 合上书之后"的组合？如果上一本也是这个结构，改。
- [ ] **金句凑数：** 是不是又凑了 5 句金句，每句下面都跟"能做什么"？如果不是实用类书，改。
- [ ] **概念卡重复：** 是不是前面用 concept 卡片列核心概念，后面"X条带走的东西"又用了一遍？改后面那个。
- [ ] **没有专属板块：** 整本书有没有一个章节，是"只有这本书适合有，换一本书就不适用"的？如果没有，加一个。
- [ ] **命名套路：** 是不是又用了"这书在讲什么""打个比方你就懂""合上书之后"这些固定标题？换个说法。

## 七、执行步骤

### 第一步：调研书籍内容

1. 使用 WebSearch 搜索书籍的目录、核心内容、读书笔记
2. 查找权威的书评、课程笔记、官方介绍
3. 多源交叉验证，确保内容准确
4. 梳理书的章节结构和核心论点

### 第二步：规划内容结构

1. **先判断这本书属于什么类型**（实用方法 / 思想经典 / 文学小说 / 知识科普 / 其他）
2. 根据类型和书的具体内容自主决定章节结构（不要套固定模板）
3. 设计一个**专属板块**——只有这本书才有的内容
4. 为每个章节提炼核心要点
5. 设计目录层级
6. 为每个章节匹配 Lucide 图标

### 第三步：生成 HTML 文件

1. 读取同目录 `template.html` 作为骨架
2. 将蒸馏内容填入 `<main class="main">` 内的 `<section>` 块
3. 为每个 `<section>` 设置唯一 `id`
4. 同步生成 `<aside class="toc">` 内的目录列表
5. 确保所有可朗读段落使用规定的 class
6. 输出文件保存到同目录 `books/分类/` 下，命名格式：`《书名》精华版.html`
   - 分类按书的类型放：心理学/战略/文学/经济学/……没有对应分类就新建
   - books/ 是蒸馏书库（主存储），需要发布时再复制到 desktop 和 web 目录

### 第四步：质量检查

**通俗易懂检查（5 条，每段内容都要过）：**

- [ ] 专业术语首次出现时，是否用日常事物解释了一遍？
- [ ] 抽象概念是否用了生活中的比方？
- [ ] 是否避免了学术腔（堆术语、长定语、被动句、嵌套从句、绕弯子）？
- [ ] 是否有"如前所述""众所周知"等假设前置知识的表达？
- [ ] 金句是不是自然摘出来的？有没有为了凑数硬拉？

**去模板化检查（5 条）：**

- [ ] 结尾是不是又用了"金句 + 读法 + 合上书之后"三件套？
- [ ] 金句是不是又凑了 5 句，每句都跟"能做什么"？
- [ ] concept 卡片是不是在书的前后重复使用了同样的呈现方式？
- [ ] 有没有一个专属板块（只有这本书才适合有的）？
- [ ] 章节命名有没有落入固定套路？

**骨架红线检查：**

- [ ] 是否基于 template.html 生成？
- [ ] `section / h2 / h3 / h4 / .callout-title / .info-box-title` 是否都出现？
- [ ] 目录 `<a href="#xxx">` 与 `<section id="xxx">` 是否一一对应？
- [ ] **`<h3>` / `<h4>` 是否都设了 `id` 并加入 TOC 二级嵌套？**（不能只把一级章节放进 TOC）
- [ ] 图标是否都是内联 SVG（无 emoji）？
- [ ] 移动端布局是否正常（≤960px 时目录应可折叠）？
- [ ] 滚动高亮是否正常（滚动某章节时目录对应项高亮）？

## 九、注意事项

1. **内容准确性**：通过多个来源交叉验证核心概念，避免错误
2. **版权意识**：这是学习笔记性质的蒸馏，引用原书内容要注明出处，不要大段原文照搬
3. **单文件原则**：输出 HTML 必须是单文件（所有 CSS/JS 内联），不能有外部依赖
4. **性能优先**：页面应该秒开，不要加不必要的动画和特效
5. **可打印性**：template.html 已内置打印样式，不要破坏
6. **每本书都要有自己的味道**：两本书放在一起，读者应该能感觉到"这两本书不一样"，而不是"这是同一个模板生成的"
